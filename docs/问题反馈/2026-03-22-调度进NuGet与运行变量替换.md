# 调度进 NuGet + 运行变量替换

日期：2026-03-22
目标：让 NuGet 包拥有 LocalDts 全部能力（调度不能只活在 `tools/` 里），并让 Web 能真正跑带参数的作业。

## 1) 调度从 CLI 搬进 `DataForge.Jobs`（NuGet）

新增 `DataForge.Core/src/DataForge.Jobs/Scheduling/JobScheduler.cs`：

- `JobScheduler.ParseSchedule(cron)` / `GetNextOccurrence(cron, fromUtc, timeZone?)`：标准 5 段 cron（Cronos，`CronFormat.Standard`）
- 实例成员：`TimeZone`、`MaxRuns`、`OnTick`（`JobScheduleTick`：本次结果 + 下次到期时间）
- `WatchAsync(job, jobFilePath, variables, ct)`、`WatchFileAsync(...)`、`GetNextRunAsync(...)`
- 内部测试缝：`Clock` / `DelayAsync`，可在测试里不真等

`Cronos` 依赖从 `tools/DataForge.Sync` 移到 `src/DataForge.Jobs`；删除 `tools/DataForge.Sync/Execution/JobScheduler.cs`（工具里不再有调度实现）。CLI `dataforge watch` 改为构造库里的 `JobScheduler` 并用 `OnTick` 打印结果与下次时间。

## 2) Web 暴露调度信息

`tools/DataForge.Web/Program.cs` 新增 `POST /api/jobs/schedule`：传 `{ yaml }`，返回 `{ schedule, next }`；无 `schedule` 字段时返回 `next: null`。

## 3) 运行变量替换（`fe390c3`，一并记录）

`src/DataForge.Jobs/Execution/VariableResolver.cs` 的 `Apply` 之前只替换部分字段，现在补齐：

- `watermark.column` / `watermark.statePath` / `watermark.initial`
- 每个 join 源的 `path` / `connection` / `table` / `on`

Web 页面加 `KEY=VALUE` 文本框（每行一条），请求体带 `variables`，`POST /api/jobs/run` 与 `/api/jobs/run/stream` 都会替换 `${KEY}`。

## 验收

- `dotnet build DataForge.Core.sln -c Release`：0 error，2 warning（均为既有 CS8425 / CS8620）
- 测试并发跑（build 一次后各项目 `--no-build`）
- 新增：`JobSchedulerTests` 7 项（时区、无 schedule 抛错、`MaxRuns` + tick、`GetNextRunAsync`）、Web `Schedule_ReturnsNextOccurrence` / `Schedule_NoScheduleReturnsNullNext`、`Run_SubstitutesRequestVariables`
- 文档：`DataForge.Jobs/README.md` 增加调度章节；缺口清单更新为「调度已进 NuGet，仍是前台进程」
