## P2 — 测试缺口 / 整洁度 / 文档对齐

### P2-1 扩展包几乎无自动化测试 — 🟡 部分

| | |
|---|---|
| **已补** | `RestApiHttpTests`；`SqlIdentifiersTests`；`FluentValidationAdapterTests`；`SqliteRoundTripTests`；`ExcelRoundTripTests`；SQL `DefaultTypeConverter` 映射 |
| **仍缺** | MySql/SqlServer 需外部库的集成测（可选） |

### P2-2 `ThenBy` / 多键排序无测试 — ✅ 已修（随 P0-3）

### P2-3 `LookupTransform` / 多数 `CommonTransforms` 无直接测试

单元测试偏管道与 CSV；转换器表驱动测试缺失。

### P2-4 `FromJsonArray` 等同 `FromJson` — ✅ 已标 Obsolete

### P2-5 `Zip` 取消令牌 — ✅ 已确认

`Zip` 现为 `second.AsAsyncEnumerable(ct)`，与主序列共用 CT。

### P2-6 公开类型未放 namespace 块一致性

多文件 `namespace X;` 后 `public class` 顶层（file-scoped 下合法）；扩展方法挂在 `DataForgePipeline` 实例上却位于各扩展命名空间——API 发现依赖 `using`。文档已强调；可考虑 `[assembly: InternalsVisibleTo]` 已列全，无额外动作。

### P2-7 文档仍可链到债单

`api-roadmap` §4「核心 Excel 占位」可链本文 P1-5；SQL 工厂规划链 P0-1/P1-6。
