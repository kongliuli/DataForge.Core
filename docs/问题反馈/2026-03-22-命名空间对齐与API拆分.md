# 命名空间对齐与 API 已实现/规划拆分（2026-03-22）

## 目标

1. 对齐文档中的命名空间 / 类型名到 0.1.0 源码
2. 将规划型 API 从可运行文档中拆出，避免与实现混淆
3. 保持构建与测试通过

## 已实现面（对照源码）

- 入口：`using DataForge.Core;` → `DataForgePipeline`
- 管道：`IDataPipeline<T>`、`IGroupedDataPipeline<TKey,TElement>`
- 验证：`IValidator<T>`、`DataValidator<T>`；FluentValidation 需 `FluentValidationAdapter<T>`
- 错误策略：`OnErrorContinue` / `OnErrorStop` / `OnErrorSkip`
- 核心导出：`To*Async`；扩展包多为 `ToExcel` / `ToJson` / `ToRestApi` / `ToSqlServer`（无 Async）
- SQL：`From*(connectionString, tableName)` 静态工厂

### 对齐修复（节选）

| 旧 | 新 |
|---|---|
| `using DataForge;` | `using DataForge.Core;` |
| `DataForgeVersion` | 删除（以 PackageVersion 为准） |
| `ToDataForge()` | `DataForgePipeline.FromMemory(...)` |
| `ContinueOnError` | `OnErrorContinue` |
| 直接 `ValidateWith(AbstractValidator)` | `FluentValidationAdapter` |
| `CollectValidationResults` 当已实现 | 标明未实现并改写示例 |
| `DataForgePipeline.FromSqlServer` | `SqlServerPipelineExtensions.FromSqlServer` |

涉及：`getting-started` / `faq` / `pipeline-guide` / `validation` / `data-sources` / `export` / `scenarios` / `transforms`，以及 `DataForge.Core/README.md` 文档链接与部分示例。
