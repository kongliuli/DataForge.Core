## 3. 已核实的文档 / 代码不一致

### 3.1 终端导出方法命名（已核实）

- README 示例：`ToJson(...)` / `ToCsv(...)` / `ToExcel(...)`
- 实际公开 API（`IDataPipeline<T>` / `DataPipeline<T>`）：`ToJsonAsync` / `ToCsvAsync` / `ToExcelAsync`
- **以源码与 `docs/API.md` 为准**；README 示例需改写。

### 3.2 管道类型签名

- CHANGELOG 曾写 `IDataPipeline<TIn, TOut>`
- 源码与架构/API 文档均为 `IDataPipeline<T>`
- **以源码为准**。

### 3.3 JSON / Excel 边界（已核实）

源码现状：

1. **核心包内置**
   - `DataForgePipeline.FromJson` / `FromJsonString` / `FromJsonArray` → 核心 `JsonSource`
   - `DataForgePipeline.FromExcel` → 核心 `ExcelSource`
2. **核心 `ExcelSource` 是占位实现**
   - 文件头注释写明：完整功能需 `DataForge.Core.Excel`
   - 实现按**逗号分隔文本**读取，并非真正 xlsx（ClosedXML）
3. **扩展包**
   - `DataForge.Core.Json`、`DataForge.Core.Excel` 另提供扩展方法与完整实现

因此：README「JSON 内置 / Excel 需扩展包」表述不完整——核心确有入口，但 Excel 核心实现不能当真实 Excel 用。

### 3.4 其他文档漂移

- 根 README「技术栈待确认」落后于项目文档（已明确 net8.0 管道库）
- CHANGELOG `[0.1.0]` 日期 `2024-01-01` vs 架构文档更新 `2026-06-11`
- `DataForgePipeline`：架构/API 称「非静态类以支持扩展方法」——类本身非 static，但工厂方法均为 `static`；扩展包多通过 `this DataForgePipeline` 注入
