# Web 独立发布产物验收（2026-10-18）

## 范围与结论

在默认测试机 air13-lab（192.168.1.12）验证 GitHub CI 产出的 Web 发布文件夹。只下载 CI artifact，没有复制源码仓库，也没有从源码构建。

首页、Catalog 类型列表和配置检查接口均返回预期结果，运行数据目录未包含在产物中。启动实例仅在回环地址监听并在检查后关闭。

这不是 NuGet.org 工具包验收，也未覆盖真实数据库迁移、SSE 进度、调度和运行历史。连接与调度数据目录需运行账号可写。

## 证据

- 产物：`dataforge-web-net8`，来自成功的 CI 运行 39086609157。
- 检查产物包含 `DataForge.Web.dll`、`DataForge.Web.runtimeconfig.json`、`wwwroot/index.html`；不包含 `data` 目录。
- 目标机 .NET SDK 8.0.411，ASP.NET Core Runtime 8.0.17。
- 在解压目录执行 `dotnet DataForge.Web.dll --urls http://127.0.0.1:15087`。
- 就绪后：
  - 首页返回 HTML 且包含配置检查按钮（`id="validate"`）。
  - `GET /api/catalog/types` 返回类型列表且包含 `sqlite`。
  - `POST /api/jobs/validate` 对不存在输入文件但配置合法的作业返回 `valid: true`，符合“不连接数据源”的预期。
- 脚本输出：`PASS: standalone CI Web artifact serves homepage, catalog and configuration validation on air13`，退出码 0。
- 检查结束后进程被停止。

## 说明

首次探测脚本误用 PowerShell 只读变量 `$HOME`，赋值失败并被重试逻辑记为就绪超时，属探测脚本错误，不是宿主缺陷；改用其他变量名后通过。
