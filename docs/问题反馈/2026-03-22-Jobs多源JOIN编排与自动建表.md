# Jobs：多源 JOIN、编排、自动建表（2026-03-22）

## 补上的痛点

| 痛点 | 做法 |
|---|---|
| N→1 多表 | YAML `sources[]` + `alias` + `on: Left = Right` 内存等值内连接 |
| 单表拆多表要跑两个文件 | 顶层 `jobs:` 顺序执行，失败即停；CLI `dataforge run` 走 `JobBatch` |
| 目标表要手写 DDL | `sink.createTable: true`（sqlite / postgresql，按首行 TEXT 建表，`keys` 作主键） |
| 重跑覆盖 | 已有 `mode: upsert` + `keys`（sqlite ON CONFLICT / postgresql ON CONFLICT） |

## 测试

`JobJoinBatchTests`：两表 SQLite join 写出 3 行；batch 第二步失败时第一步已写入。
Sync 测试（排除本机 PG 场景）：15 通过。

## 限制

- JOIN 把各源读进内存，适合迁移规模，不是大表流式 join
- 自动建表类型一律 text，不做类型推断
- 坏行导出仍只在单源管道路径（`BuildPipeline`）生效
